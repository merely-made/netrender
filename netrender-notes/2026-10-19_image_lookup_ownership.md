# Image lookup and invalidation ownership

The simple and tiled Classic rasterizers maintained separate copies of CPU-image cache refresh policy. Simple, tile, overlay and retained-fragment paths then cloned those caches and merged texture overrides before lowering. Tile and retained-run lowering rebuilt another map from that already merged map.

Both rasterizers now use one `CpuImageCache` implementation for source lifetime. Lowering borrows an `ImageLookup`: explicit texture overrides win, then retained CPU sources, then fragment-local or ordinary scene sources. The public cache-only entry point still uses only its supplied map. Scene-image conversion has one format/alpha policy. The immutable-image-key contract is unchanged. No atlas-upload speedup is claimed; this removes map construction directly visible in source, not a measured upload cost. The separate `IMG-BLOB-IDENTITY` measurement remains deferred.

Retained-path testing also reproduced two existing filtered-placement failures on a freshly compiled, clean `c5efc94f876e93caba20807709189c5f9589492b` control. A newly registered filter output invalidated every retained fragment, including the unrelated fragment just drawn into the filter scratch target. The override owner now invalidates the master and affected fragment lowerings by image key. Callers retain responsibility for their tile-cache invalidation, but do not repeat the owner's fragment invalidation. Filter slot bookkeeping tracks lifetime membership; dimensions and refresh-versus-registration decisions belong to the rasterizer.

Done conditions: actual image/pattern pixels, override collision and removal, retained fragment-local sources and direct runs, moving filtered fragments without unnecessary re-lowering, replacement/retirement, existing image and layer suites, and feature-off compilation. Keep the 5 GiB/no-swap, 150% CPU, one-job/one-test-thread, shared-lock, 600-second gate limits.
